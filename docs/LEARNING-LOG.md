# Rota Learning Log

### 2026-10-15 — Monorepo Architecture & Database Partitioning
Setting up the Rota architecture highlighted the critical difference between control-plane and tenant data. By strictly isolating team data across two shards (`rota_shard_0` and `rota_shard_1`) and directing global identities (`users`, `sessions`, `team_directory`) to a control plane, we eliminate cross-tenant data leaks at the infrastructure level. Enforcing pure SQL migrations and strict composite foreign keys `(team_id, id)` ensures data integrity without relying on ORM magic. Separating Redis into a dedicated cache instance with TTLs and an eviction-free BullMQ queue instance guarantees that heavy background workloads won't drop jobs or starve session invalidations.

### 2026-10-16 — Concurrency, Advisory Locks, and Swaps (Tiers 3–4)
Managing shift assignment concurrency taught us that database isolation levels alone are insufficient under high write volume. Using `pg_advisory_xact_lock(hashtextextended(membership_id::text, 0))` before overlap evaluation serializes scheduling mutations per employee cleanly without locking the entire table. For swap workflows, implementing direct colleague handoffs with row-level locks, colleague consent, and manager approval in a single transactional unit prevents double-assignment anomalies and race conditions.

### 2026-10-16 — Cursors, Visibility Filtering, and High Volume (Tier 5)
Designing an append-only activity feed with 10,000+ events demonstrated that offset pagination degrades rapidly with deep pages. Enforcing base64url-encoded composite cursors `{createdAt: created_at::text, id}` that preserve microsecond precision directly from PostgreSQL text strings avoids JavaScript `Date` truncation. Filtering visibility at the query boundary (or in-memory on cached first pages) protects privacy without leaking owner-only billing items to staff.

### 2026-10-17 — Subscriptions, Idempotent Ledgers, and Off-Line Sanitization (Tiers 6–7)
Building the billing engine on an append-only ledger showed the power of event-sourced financial records. Never updating or deleting a ledger row and writing zero-amount adjustment records on downgrades makes billing audits and state reconstruction deterministic. In the mobile offline cache, persisting strictly one query (upcoming published shifts for 30 days) and omitting shift notes and draft shifts completely protects user privacy on shared mobile devices.

### 2026-10-17 — Cache Invalidation, Tenant Roster Caching, and k6 Load Optimization (Tier 8)
During our k6 load test with 200 concurrent virtual users, we uncovered an important bottleneck: running shift backfills inside the cache hit path saturated the 20-connection pool. By moving backfill strictly into the cache miss branch and caching active tenant rosters (`team:{id}:roster:v{n}`), we reduced tenant lookup database overhead to zero on cache hits. The p95 response time dropped from 338 ms to 38 ms with a 0.00% error rate across 3 minutes of steady-state load testing.

### 2026-10-17 — Design Tokens, Screen Reader Accessibility, and Production Hardening (Phase 9)
Preparing Rota for production release underscored that enterprise design systems require automated rigor beyond aesthetic styling. Running automated grep audits across the codebase ensured zero hardcoded color strings, zero named colors, zero primitives outside `src/theme/`, zero raw spacing numbers, and zero unscaled typography. Evaluating WCAG 2.1 relative luminance formulas mathematically proved that every text color role in both Light and Dark modes comfortably exceeds the 4.5:1 minimum threshold (ranging up to 16.99:1). In screen reader and TalkBack support, guaranteeing 48x48 pt minimum touch targets and explicit semantic labels transforms assistive usage from an afterthought into a first-class experience. On the backend, implementing Sentry `beforeSend` scrubbing and Pino redaction ensures that authorization tokens, employee shift notes, and payment tokens can never leak into monitoring dashboards. Finally, analyzing Apple Guideline 3.1.1 and Google Play Billing demonstrated why SaaS B2B platforms rely on web-based subscription management or native store billing bridges while using test-mode payment adapters during staging.
